# Amber Specialty Coffee

Статический сайт на Vue 3, TypeScript, Vite, Pinia и Vue Router. Reka UI обеспечивает доступные диалоги и выбор вариантов. Заказы передаются в WhatsApp подготовленным текстом; отправку выполняет пользователь, заказ подтверждает оператор.

## Запуск

Рекомендуется Node.js 24 LTS. Установка: `npm ci`. Разработка: `npm run dev`. Сборка: `npm run build`. Проверки расчетов и сообщения: `npm test`. Линтер: `npm run lint`.

## Изменение материалов

- Меню: `src/data/menu.json`. 44 блюда, 71 напиток. Поле `categories` допускает несколько категорий для одного товара. Цены вариантов находятся в `variants`, а не в сохраненной корзине.
- Номер WhatsApp, адреса и график: `src/data/config.ts`.
- Логотип: `public/brand/amber-logo.svg` и `public/brand/amber-mark.svg`. Сейчас временная реконструкция предоставленного изображения.
- Фото: `public/images/*.webp`. Исходники и ссылки на источник: `assets/menu/manifest.json`.
- Цвета, адаптивность и оформление: `src/style.css`.

`npm run images` повторно подготавливает WebP и временные брендовые файлы из исходников. После получения оригинального логотипа обновить этот скрипт, чтобы он не перезаписывал оригинал.

Вспомогательный `scripts/prepare-menu.py` использован для первого импорта из AMBER-MENU.md. Рабочий источник сайта — `src/data/menu.json`; повторный запуск импорта перезапишет ручные изменения.

## Сценарий заказа

Корзина сохраняется в localStorage. При восстановлении проверяются ID, объём и количество, цены берутся из актуального меню. Контактные данные формы не сохраняются постоянно. При доставке требуется адрес; при самовывозе — выбор одной из двух кофеен. Стоимость доставки не включается в сумму товаров, ее уточняет оператор. После валидации доступен просмотр полного текста, ссылка WhatsApp и копирование.

Сайт не может проверить отправку сообщения и не показывает ложное подтверждение заказа. Ссылка WhatsApp проверена на тестовых данных без отправки сообщений.

## Публикация

GitHub Actions проверяет линтер, тесты и сборку при обновлении `main` и в pull request. После подключения собственного домена обновление `main` будет автоматически публиковаться на `https://ambercoffee.ru/`. В настройках репозитория **Settings → Pages → Build and deployment → Source** должен быть выбран **GitHub Actions**, а в **Custom domain** — `ambercoffee.ru`.

Для собственного домена сборка использует `VITE_BASE_PATH=/`; локально путь также остаётся `/`. В артефакт добавляется копия `index.html` как `404.html`, чтобы прямые ссылки на `/checkout` и `/privacy` открывали приложение. У регистратора корневой домен должен указывать на четыре A-адреса GitHub Pages, а `www` — через CNAME на `mohdan-barzankaev.github.io`. Отдельный хостинг и CNAME-файл в репозитории при публикации через GitHub Actions не нужны. [Документация GitHub Pages](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

Страница `/privacy` описывает фактический сценарий передачи данных; она не заменяет юридические документы оператора. Перед публичным запуском предоставить окончательные документы и реквизиты владельца кофейни. Для органического поиска при необходимости добавить генерацию HTML публичных страниц на этапе сборки.

Локальные шрифты и изображения позволяют обходиться без запросов к Taplink и Google Fonts при просмотре сайта. Аналитика и сторонние виджеты не подключены.

При поддержке экспериментального WebMCP сайт предоставляет чтение меню, корзины и добавление товаров в корзину для просмотра. Эти инструменты не отправляют сообщения и не оформляют заказ автоматически.
