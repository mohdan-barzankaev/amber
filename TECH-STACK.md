# Предлагаемый стек Amber

Пользователь предложил Vue 3, Pinia и Vue Router. Ниже — рекомендуемое дополнение для статического сайта с заказами через WhatsApp. Стек установлен, первая рабочая версия реализована.

## Основной стек

- Vue 3, Composition API, однофайловые компоненты с script setup.
- TypeScript в строгом режиме: типы товаров, вариантов, корзины и формы.
- Vite: разработка и сборка статических файлов.
- Pinia: состояние корзины, количество, выбранные варианты. Итоги вычислять из актуального каталога.
- Vue Router: главная, меню, оформление и документы; карточки блюд можно открывать в диалоге.
- Reka UI: доступные примитивы диалогов, вкладок, переключателей; собственное оформление Amber.
- Обычный CSS: переменные для цветов, размеров и шрифтов, scoped-стили компонентов. Tailwind и SCSS для начального объема не требуются.
- VueUse: сохранение корзины через useStorage, копирование текста через useClipboard и другие утилиты по необходимости.
- Zod: проверка формы и сохраненной корзины. Не добавлять отдельную библиотеку форм для простой формы заказа.
- @lucide/vue (актуальный пакет Lucide для Vue): отдельные импортируемые иконки, без подключения полного набора.

## Инструменты качества

vue-tsc, ESLint и Prettier. Vitest для расчетов корзины, вариантов товаров и форматирования WhatsApp-сообщения. Полный сценарий от каталога до подготовленного сообщения проверить в браузере на телефоне и компьютере.

## Данные и ограничения

Меню — локальные типизированные данные, фото — статические файлы. Номер WhatsApp и контакты — отдельная конфигурация. Изменение меню требует редактирования данных и повторной публикации. Онлайн-админка не входит в этот вариант.

В localStorage сохранять позиции и выбранные варианты корзины; контактные данные формы по умолчанию не сохранять. Хранимую цену не считать источником истины: восстановленную корзину сверять с актуальным меню.

Сайт генерирует текст и ссылку WhatsApp; пользователь отправляет сообщение, оператор подтверждает и оформляет заказ. API-клиент и серверные библиотеки не нужны для согласованного сценария.

## Публикация и маршруты

Статический хостинг. Для красивых URL с createWebHistory настроить возврат index.html для маршрутов приложения на хостинге. Если такая настройка недоступна, использовать hash-маршрутизацию. Это настройка раздачи файлов, без бэкенда приложения.

При необходимости поискового продвижения предусмотреть предварительную генерацию HTML публичных страниц на этапе сборки; обычная SPA сама по себе не гарантирует полноценную индексацию и корректные превью всех маршрутов.
